## Device instruments this implies (next session; all EL1-safe unless marked)

1. **uH log ring sampler (E2, low risk now)**: copy first 4 KiB @0x87100000 from the not-offered-A55 stub
   (m4pcs1 pattern) → WINPRAM every 0.25 s. Static stage-2 maps it RO to the guest (verified 0x47f HAP=RO),
   and uH writes ~20 ASCII lines into it at boot - a sane first read prints the banner
   `UH64_23d99e21 ... exynos9820` from UEFI (a single 8-byte read, logged). If Windows-era lines appear at
   an M4 death, they name the fault; if uH ever reaches uh_panic, the SoC resets via PMU 0x1586080C while
   the faulting core spins at EL2 (matches the "one core never answers, no bugcheck" death shape).
2. **Per-core uH-state probe (`hvc #0`, CAUTION)**: uH's HVC handler ignores imm != 0xC300cXXX and erets
   (returns). A parked stub does: mailbox "HVC0 pre" -> `hvc #0` -> mailbox "HVC0 post" -> UEFILOG.
   * post appears -> uH's vectors/HCR ARE installed on that core class;
   * core dies / SoC resets -> EL2 state on that core is cold (no uH) - that asymmetry (boot CPU under
     s2 vs secondaries without, or M4 vs DSU) is itself the smoking gun for cross-cluster attribute
     mismatch. Try it first on the boot CPU (UEFI-time, guaranteed warm), then A55/A75 secondaries, M4 last.
3. **Memory-map split experiment**: UEFI memory map excluding PA 2-4GB (keep only what's needed for MMIO/
   reserved) so Windows RAM lives at PA >= 4GB (fault-path s2 entries instead of the static 0x4fd NS blocks),
   8 cores offered. If the heap-corruption signature moves/disappears, the stage-2 NS window is causal,
   and the permanent fix is to make uH map those PAs too (HVC-side) or never touch PA 2-4GB with Windows.
4. **T2/T3 (m4/tasks.md) unchanged and still first**: cross-cluster ordering/lock tests - they now have an
   added axis: run the pattern once with the shared pages in the PA 2-4GB window (s2 NS) and once at
   PA >= 4GB (fault-path attrs): different outcomes = s2-shareability lead confirmed; identical = s2 is a
   red herring and the T2 patterns must be extended (NC pages, Windows attrs per T3).
5. Not-for-device (owner's side): fetch `uhuh.bin` (UHCFG partition) and `acpm.bin` (ACPM partition) from a
   full stock dump - uhuh.bin may configure uH policies (per-CPU bring-up!) and ACPM owns M4 rail voltage.
